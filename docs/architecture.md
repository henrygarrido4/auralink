# Architecture

The Auralink Studio website is a statically generated Astro site. Every page is rendered to HTML at build time, served by Netlify from `dist/`, and enhanced with small Vue islands only where interaction is required. There is no application backend, database, or authentication.

## Inspira UI integration notes

- `@inspira-ui/plugins` ships Tailwind plugins as named exports (`addBackgrounds`, `addVariablesForColors`, `setupInspiraUI`). Tailwind 4's `@plugin` directive needs a default export, so `src/styles/inspira-backgrounds.mjs` re-exports `addBackgrounds` (utilities `bg-grid`, `bg-grid-small`, `bg-dot`). `addVariablesForColors` is skipped because Tailwind 4 already exposes theme colours as `--color-*` variables.
- Inspira components expect shadcn-style CSS variables and sometimes a `.dark` class that this project does not define globally; the adoption checklist in the `inspira-component` skill covers mapping them to daisyUI tokens per component, dependency approval, server-rendering guards, accessibility, and a per-page Lighthouse comparison.
- Not verified at setup: the complete CSS variable block from the Inspira installation page (only partially retrieved) and whether specific components require `reka-ui` or shadcn-vue primitives. Check each component's imports when adopting it. No component has been adopted yet.

## Booking and the contact tabs (2026-11-20)

The owner asked for two ways in on the contact page, booking the free discovery call or sending the inquiry, and approved the address, the number, and the Calendly event for display (`contactDetails` and `contactRoutes` in `src/data/site.ts`; `docs/content-strategy.md`, "Contact page: booking and messages").

**Tabs without an island.** `ContactOptions.astro` renders both panels in the HTML, one after the other, with the tab bar `hidden`; `src/lib/contact-tabs.ts`, run from the component's `<script>`, turns them into the WAI-ARIA tabs pattern (roles, `aria-selected`, `aria-controls`, `aria-labelledby`, roving `tabindex`, Left and Right arrows, Home and End, Enter and Space, manual activation) and keeps the panel not chosen `hidden`, so its controls leave the tab order while keeping everything they hold. The chosen tab is the URL's fragment (`#book-call`, `#send-message`), written with `pushState` on a click, so direct links, fragment links on the page, and Back and Forward all choose a tab, and nothing scrolls or moves focus on a switch. A small `is:inline` script after the card applies the first choice while the HTML parses, so the page never paints both panels and then hides one. A plain script and not a Vue island for the reasons the form has: the Netlify form must stay the plain HTML Netlify detects, the state is one fragment, and the page still loads no framework runtime. Without JavaScript both panels show in turn under their own headings.

**Calendly, the one third-party script.** The booking panel (`BookingCalendar.astro`, `src/lib/booking-embed.ts`) embeds the event with Calendly's documented inline embed: `widget.js` from `assets.calendly.com` is fetched once the page has loaded and the browser is idle, never before render, and `Calendly.initInlineWidget({ url, parentElement, resize: true })` is called only while the booking panel is on show, once; switching tabs hides and shows the same iframe. The event's details are hidden in the embed (`hide_event_type_details=1`, available on every plan, since the panel states them); colour options are not used (they need a paid plan) and the cookie banner and branding stay. The container is at least 320px wide at every width (the card runs edge to edge below `sm`), Calendly sets its height from the booking page, and the placeholder over it holds the "Open booking calendar" link to the same event until Calendly has shown itself; the script's failure, or twenty seconds without a sign of Calendly, leaves the placeholder with the link. Calendly keeps availability, time zones, and the booking; no API key, backend, or second scheduler exists. The embed's own cost is Calendly's: its iframe fetches about 3.6 MB of Calendly's and Stripe's scripts and styles and sets their cookies, which Lighthouse's third-party-cookies audit counts against the page, so `lighthouse.budgets.json` gives `/contact/` its own allowance for that embed and the audit script counts transfer budgets against the site's own resources only (`docs/performance.md`, "Budgets"). The page's own performance is unchanged: score 1, TBT 0 ms, CLS 0, since nothing of Calendly loads before the page has.

**Where the links lead.** The navbar's, the home hero's, and the closing banner's "Book a free call", and the home directory's "Let's talk", lead to `/contact/`. The service cards' inquiry fallback (`primaryCta.href`) leads to `/contact/#book-call`; "Ask something else" on the detail pages and "Have a question?" on the pricing page to `/contact/#send-message`; the pricing packages' buttons also lead to `/contact/`, which opens on the booking tab.
