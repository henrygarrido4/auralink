# Quality checks

All checks are npm scripts so they run the same way for people, Cursor, Claude, and CI. Run the narrowest relevant check while working and the full suite before finishing. This page also holds the requirement-to-evidence table from the setup audit and the task-routing review of the instruction system.

Engine-independent suites (seo, layout, rendering) run only in desktop Chromium to avoid multiplying identical assertions. Mobile projects are browser emulations, not physical devices. Routes are discovered from `dist/` by `tests/e2e/routes.ts`, so new pages are covered automatically. The tests that walk every route in one test (a11y, seo, rendering, motion, layout, page-hero) set their timeout from the route count, so the site can grow without the 30-second default cutting them short (since 2026-11-20, when 22 detail pages brought the count to 27). WebKit mirrors Safari in skipping links on plain Tab, so the keyboard tests press Alt+Tab there. Playwright's WebKit is newer than the Safari visitors run, so a WebKit pass does not prove Safari renders the same: Safari 27.2 left the navbar call to action's aura lit after the pointer left (a repaint bug WebKit fixed on 2026-10-09), which no browser in the matrix shows. The navigation suite checks that this light fades through its strength, never its colour, and paint or motion changes still need a look in Safari itself.

### Changing thresholds

Title and description lengths, the viewport list, the overflow rules, the WCAG tag set, and the zero-violation policy are deliberate. Changing any of them requires a short entry in the decision log below with the reason. Performance budgets have their own log in `docs/performance.md`.

Decision log:

- 2026-11-16: initial thresholds set (title 10-70, description 50-160, WCAG 2.2 AA tags, zero axe violations).
- 2026-11-16: viewport widths 360, 390, 768, 1024, 1440, 1920 added; Firefox, WebKit, and mobile WebKit projects added.
- 2026-11-18: the five-second motion check allows the home services strip to keep scrolling. Any other animation still running after five seconds fails. The strip first shipped with a Pause button; the owner removed it the same day and asked for a pause under the pointer only. That leaves keyboard users with no way to stop the strip, which WCAG 2.2.2 asks for when motion runs longer than five seconds. Reduced motion still shows a static row. Do not copy this exception to other motion.
- 2026-11-18: the five-second motion check also allows the light on the hero's benefit ring to keep circling. It had circled only under a hovering pointer; the owner asked for it to stay on all the time. Nothing pauses it, by pointer or keyboard, which WCAG 2.2.2 asks for when motion runs longer than five seconds. Reduced motion leaves it off. Do not copy these exceptions to other motion.

## Known log noise

- `[WARN] [glob-loader] No files found matching ...` appears during `astro sync`, `astro check`, and builds until a collection has at least one non-draft-prefixed entry. It is harmless and disappears once content exists.
- Astro 7 auto-detects AI agent sessions (Cursor, Claude Code) and starts `astro dev` and `astro preview` as background processes. The Playwright web server and the perf script pass `--ignore-lock` to get a one-off foreground server they can stop; if a preview server ever lingers on port 4322 or 4323, find it with `lsof -nP -iTCP:4322 -sTCP:LISTEN` and `kill <pid>`.
- If a Playwright run reports many `h1` elements or unexpected buttons (Menu, Inspect, Audit, Settings), it hit an `astro dev` server instead of the preview build; the smoke spec fails fast with a message. Stop stray servers with `astro dev stop` and rerun.
- `npm warn install-scripts` about `fsevents` during `npm install` is an npm notice on macOS and needs no action.

## Manual checks for new templates

Automation does not cover everything. For each new page template or interactive component:

1. Keyboard pass: Tab through the page (Alt+Tab in Safari or WebKit to reach links), operate every control, close overlays with Escape, confirm focus is visible and never hidden behind sticky elements.
2. Screen reader spot check with VoiceOver on macOS: headings list, landmarks, link names, form labels and errors.
3. Zoom to 200% and a 320px wide viewport: no horizontal scrolling or clipped content.
4. Reduced motion enabled in system settings: no essential information depends on animation.
5. Inspect the layout screenshots in `reports/screenshots/` at every width and describe what you saw (`.cursor/skills/responsive-qa/SKILL.md`).
6. `npm run perf:audit` and compare with `docs/performance.md`.
7. Read the page as a prospective client: does the first paragraph answer the question, and is the next step obvious?
8. Before launch: a pass on at least one physical iPhone and one Android phone; emulation does not replace it.
9. A link whose colours fade on hover or focus: in installed Chrome, open its destination, come back, and hover it. Chrome paints a visited link by its own rules, and no suite shows them: computed styles report the unvisited colours, Playwright's contexts keep no history, and its Chromium did not have the fault that put a near-black edge on the home service cards' arrow boxes (Chrome 157 and 158, 2026-11-19; `.cursor/rules/styling-tailwind-daisyui.mdc`).

## Definition of done

1. Requested behaviour implemented; nothing unrelated changed.
2. `npm run quality:static` passes.
3. `npm run test:e2e:chromium` passes for routine changes; `npm run test:e2e` passes when pages, layouts, islands, forms, metadata, or shared components changed.
4. Performance budgets hold (`node scripts/perf-audit.mjs --no-build` after a build) when assets, scripts, fonts, islands, or templates changed.
5. Content follows `docs/content-strategy.md`; no unverified claims.
6. Metadata and structured data correct for the page type.
7. Accessibility basics verified (automated plus the manual list for new templates).
8. Docs and instruction files updated when conventions, commands, or structure changed; `npm run check:workflow` passes.

## Continuous integration

`.github/workflows/quality.yml` mirrors `npm run quality:full` with one build: `npm ci`, static checks, build, Playwright browsers with OS dependencies, the five-project matrix (`PLAYWRIGHT_SKIP_BUILD=1`), the Lighthouse audit of the sample with budgets (`--sample`), and an artifact upload of `playwright-report/`, `test-results/`, and `reports/` on every run. It runs on GitHub (`henrygarrido4/auralink`) for pushes to `main` and for pull requests. When the browser matrix fails, the Lighthouse step is skipped. The job's limit is 45 minutes (from 30, 2026-11-20): with thirty pages the matrix alone takes about thirteen minutes, and a job cancelled at its limit reports nothing.

Run history: the first two runs, on 2026-11-17 (commits `846865b` and `71c2e66`), passed the static checks and the build, then failed the same seven browser tests. The hero underline test failed in all five projects, because DejaVu Sans, the runner's default sans-serif, wrapped "brings them back." onto two lines. Mobile WebKit failed the reduced-motion and colour-scheme tests, because WebKit styles the page once before the stylesheet arrives and the reduced-motion rule turned the stylesheet's arrival into transitions. The fixes are in `src/components/sections/Hero.astro` and `src/styles/global.css`. With the phrase on one line, Firefox then misreported the underline's length, fixed in `src/components/ui/PencilUnderline.astro`. On 2026-11-17 the fixes passed all 135 tests in the Linux container below, and then on GitHub: [run 44244297213](https://github.com/henrygarrido4/auralink/actions/runs/44244297213) (commit `92d00fc`) was the first fully green run, with 135 tests passed in all five projects and the Lighthouse step within budget. On 2026-11-20, [run 44825131550](https://github.com/henrygarrido4/auralink/actions/runs/44825131550) (commit `040e576`, the detail pages) passed 596 tests and failed one, in desktop Firefox only: the detail-pages suite's no-JavaScript test asserted a disclosure had opened with `toHaveJSProperty('open', true)`, which Playwright evaluates in the page's script world, and Firefox provides none while JavaScript is off, so the expect hung until the test timeout. ### Reproducing CI on Linux

Linux renders and times pages differently from macOS, so check a platform-specific failure in a Linux container instead of trusting a macOS pass. The container also runs Firefox, which cannot start on macOS 27.2. With Docker (OrbStack on the owner's Mac):

```sh
# Playwright's Ubuntu 24.04 image for the installed Playwright version, plus DejaVu fonts:
# the GitHub runner's default sans-serif, which the official image does not include.
printf 'FROM mcr.microsoft.com/playwright:v1.65.1-noble\nRUN apt-get update && apt-get install -y --no-install-recommends fonts-dejavu-core\n' | docker build -t auralink-ci-repro -
# Work on a copy: Linux needs its own node_modules.
rsync -a --exclude node_modules --exclude dist --exclude .astro --exclude .git ./ /tmp/auralink-linux/
docker network create --ipv6 --subnet fd00:a17a:11c1::/64 auralink-v6  # once; see below
docker run --rm --ipc=host --network auralink-v6 -e CI=true -v /tmp/auralink-linux:/work -w /work auralink-ci-repro \
  bash -lc 'npm ci && npm run quality:static && npm run build && PLAYWRIGHT_SKIP_BUILD=1 npx playwright test && node scripts/perf-audit.mjs --no-build --sample'
```

It reproduced both failed GitHub runs exactly, down to the measured offsets (the underline 130.728 px off in Chromium and 129.25 px in Firefox). It differs from the runner in CPU architecture (arm64 on Apple Silicon, x86-64 on GitHub) and Node version (the image's, not 24). Change the image tag whenever Playwright is upgraded.

The IPv6 network is for the Lighthouse step. On Docker's default network the container has no IPv6 address apart from loopback, so `astro preview` listens on `::1` only while Node's `fetch('http://localhost:4323')` connects over IPv4, and `scripts/perf-audit.mjs` stops with "preview server did not respond". The browser tests are unaffected. GitHub's runner did not have this problem when it first reached the step, in run 44244297213; if the step ever fails there with that message, this mismatch is the cause.
